# Metrics และ Charts

อ่านเมื่อสร้างหรือเปลี่ยน KPI, chart, ranking และข้อความสรุปตัวเลข

## Metric Contract

ก่อนออกแบบตัวเลข ระบุชื่อ ความหมาย หน่วย entity ที่นับ population, numerator/denominator, inclusion/exclusion, time field/timezone, filter scope และแหล่งข้อมูล
ตรวจ freshness และสถานะข้อมูล: สดจากระบบ, delayed, partial หรือ cached; แสดงเมื่อมีผลต่อการตัดสินใจ
อย่าเปลี่ยน query/business definition เพื่อให้กราฟดูลงตัวโดยไม่มีข้อกำหนดรองรับ

ตัวอย่างความต่างที่ห้ามกลบด้วยชื่อเดียวกัน:

- “รับเข้าในช่วงเวลา” เป็น flow; “คงค้าง ณ วันสิ้นงวด” เป็น snapshot
- “อัตราสำเร็จ” ต้องบอกฐานที่ใช้หาร; จำนวนสำเร็จเพิ่มไม่ได้แปลว่าอัตราดีขึ้น
- ค่าเฉลี่ยรายกลุ่มรวมกันต้องถ่วงน้ำหนักเมื่อฐานไม่เท่ากัน; อย่าเฉลี่ย percentages ตรง ๆ
- ประวัติหลายรายการต่อ entity อาจทำให้ join นับซ้ำ ต้องแยกจำนวน entity กับจำนวน event

## KPI Card

แสดง label ที่เข้าใจได้ ค่า หน่วย และ context ที่จำเป็น เช่น ช่วงเวลา/ฐานเปรียบเทียบ
Delta ต้องมี comparison period ที่เทียบกันได้และทิศทางดี/ไม่ดีตาม domain ไม่ถือว่าตัวเลขเพิ่มเป็นสีเขียวเสมอ
แยก percent change กับ percentage-point change; เมื่อฐานเดิมเป็นศูนย์อย่าแสดง Infinity หรือสรุปเปอร์เซ็นต์ที่นิยามไม่ได้
แยก zero, unknown, not applicable และ loading ไม่ใช้ 0 แทนทุกสถานะ
Card ที่คลิกได้ต้องมีชื่อปลายทาง focus และ keyboard behavior; card อ่านอย่างเดียวไม่ควรใช้ hover/cursor ที่ชวนให้คิดว่าคลิกได้

## เลือกกราฟตามคำถาม

| คำถาม | ตัวเลือกเริ่มต้น | ข้อควรระวัง |
|---|---|---|
| เปลี่ยนตามเวลาอย่างไร | Line; column สำหรับช่วงเวลาที่แยกชัด | เรียงเวลา รักษาช่วงว่าง ไม่เชื่อม missing data ให้ดูเป็นค่าจริง |
| กลุ่มไหนมากที่สุด | Horizontal bar ที่เรียงอันดับ | หน่วยตรงกัน ชื่อยาวอ่านได้ ระบุ top-N และส่วนที่ตัดออก |
| แต่ละส่วนเป็นเท่าไรของทั้งหมด | Stacked bar; donut เมื่อหมวดน้อยและรวมเป็น whole จริง | กลุ่มซ้อนทับห้ามทำเหมือนแบ่งทั้งก้อน; หมวดมากใช้ bar/table |
| ค่าอยู่ห่างเป้าเท่าไร | Bar พร้อม target/reference line | เป้าต้องมีแหล่งอ้างอิง ไม่สร้าง threshold เพื่อแต่งสี |
| การกระจายเป็นอย่างไร | Histogram/box plot ตามความเข้าใจผู้ใช้ | บอก bin/หน่วยและ outlier; อย่าใช้ค่าเฉลี่ยแทน distribution |
| ต้องอ่านค่าตรงหรือทำงานต่อ | Table | ไม่บังคับกราฟหากตารางช่วยงานได้ดีกว่า |

เลือกจำนวนกราฟจากคำถามที่ต่างกัน ไม่เพิ่มกราฟสองชนิดที่เล่าเรื่องเดียวโดยไม่เพิ่มประโยชน์
หลีกเลี่ยง 3D และ dual axis ที่ทำให้เปรียบเทียบผิด; ถ้าต้องใช้หลาย scale ให้แยก chart หรืออธิบาย scale ชัด
Bar ควรเริ่มจากศูนย์เพื่อรักษาความหมายความยาว; line ที่ไม่เริ่มศูนย์ต้องแสดงแกนชัดและไม่ขยายความผันผวนจนชวนเข้าใจผิด

## Labels, Tooltip และ Legend

รักษาสีของ series เดียวกันข้ามกราฟและการเปลี่ยน filter ไม่ใช้ลำดับ response เป็นตัวกำหนดสี
Tooltip แสดงชื่อเต็ม ค่า หน่วย ช่วงเวลา และฐานเปอร์เซ็นต์ตามจำเป็น ไม่ฝากข้อมูลสำคัญไว้กับ hover อย่างเดียว
รองรับ touch/keyboard หรือมีตาราง/ข้อความเทียบเท่าเมื่อ chart library ทำไม่ได้
ชื่อยาวควร wrap หรือมีทางอ่านชื่อเต็ม; อย่าซ่อนความต่างของหมวดหลัง ellipsis
ใช้รูปแบบจำนวน/วันที่ตาม locale อย่างสม่ำเสมอ ระบุการปัดเศษและหน่วยย่อเมื่ออาจทำให้ตีความผิด

## ตรวจความสอดคล้อง

ใช้ fixture ขนาดเล็กที่คำนวณด้วยมือได้ ทดสอบ 0, null, กลุ่มเดียว, ชื่อยาว, ค่ามาก, tie, missing period และหลายกลุ่ม
เทียบ KPI, chart, detail และ export ที่ควรใช้ population เดียวกัน หาก scope ต่างให้ติดป้ายแยก
กราฟร้อยละต้องใช้ denominator ถูกต้อง ไม่บังคับให้รวม 100% เมื่อหมวดซ้อนทับ
ข้อความ “ดีขึ้น/ลดลง/สูงที่สุด” ต้องมีข้อมูลรองรับ; ข้อเสนอแนะเชิงสาเหตุไม่อาจพิสูจน์จาก correlation เพียงอย่างเดียว
