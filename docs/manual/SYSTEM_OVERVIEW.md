# คู่มือภาพรวมระบบรับเรื่องร้องเรียนศูนย์ดำรงธรรมจังหวัดศรีสะเกษ

เอกสารนี้อธิบายว่าระบบคืออะไร มีที่มาจากปัญหาใด ใครเป็นผู้ใช้งาน และระบบปัจจุบันรองรับฟังก์ชันใดบ้าง โดยสรุปจากเอกสารข้อกำหนด เอกสารออกแบบ และ Implementation ที่มีอยู่ในโปรเจกต์

> ชื่อระบบ: **ระบบรับเรื่องร้องเรียนศูนย์ดำรงธรรมจังหวัดศรีสะเกษ**<br>
> ชื่อภาษาอังกฤษ: **Damrongdham Complaint Management System (DCMS)**<br>
> ชื่อที่แสดงในหน้าเว็บ: **Sisaket E-CMS**<br>
> ขอบเขตพื้นที่: **จังหวัดศรีสะเกษ**<br>
> อัปเดตล่าสุด: 14 กันยายน 2569

## 1. ระบบนี้คืออะไร

DCMS เป็น Web Application สำหรับบริหารจัดการเรื่องร้องเรียนและร้องทุกข์ของประชาชน ตั้งแต่การรับเรื่อง คัดกรอง จัดประเภท ส่งต่อหน่วยงาน ติดตามความคืบหน้า ตรวจสอบผล และปิดเรื่อง รวมถึงจัดทำ Dashboard รายงาน และการแจ้งเตือนสำหรับเจ้าหน้าที่และผู้บริหาร

ระบบทำหน้าที่เป็นศูนย์กลางข้อมูลระหว่าง 3 ฝ่ายหลัก ได้แก่

1. **ประชาชน** — ยื่นเรื่อง ส่งหลักฐาน และติดตามผล
2. **ศูนย์ดำรงธรรมจังหวัดศรีสะเกษ** — รับเรื่อง คัดกรอง ส่งต่อ ติดตาม ตรวจผล และปิดเรื่อง
3. **หน่วยงานที่รับผิดชอบ** — รับเรื่อง ดำเนินการ บันทึกความคืบหน้า และส่งผลกลับให้ศูนย์ดำรงธรรม

ทุกเรื่องใช้เลขที่อ้างอิงรูปแบบ `DC-YYYYMM-XXXX` และมีประวัติการดำเนินงานต่อเนื่องตั้งแต่เริ่มรับเรื่องจนสิ้นสุดกระบวนการ

## 2. ที่มาและความจำเป็นของระบบ

ระบบนี้เกิดขึ้นเพื่อแก้ข้อจำกัดของการบริหารเรื่องร้องเรียนด้วยสมุด เอกสาร หนังสือราชการ ไฟล์ Excel หรือการประสานงานแยกกันหลายช่องทาง ซึ่งทำให้ข้อมูลกระจัดกระจาย ติดตามยาก และเสี่ยงต่อการตกหล่น

ปัญหาสำคัญที่ระบบต้องการแก้ไข ได้แก่

| ปัญหาเดิม | แนวทางที่ระบบเข้ามาช่วย |
|---|---|
| ข้อมูลเรื่องร้องเรียนอยู่หลายแหล่งและค้นหายาก | รวมเรื่องร้องเรียนและหลักฐานไว้ในฐานข้อมูลกลาง |
| ไม่ทราบว่าแต่ละเรื่องอยู่ขั้นตอนไหนหรือใครรับผิดชอบ | ใช้ Workflow สถานะ การมอบหมาย และ Timeline ที่ตรวจสอบได้ |
| การส่งต่อหน่วยงานไม่มี Tracking ที่ชัดเจน | บันทึกหน่วยงาน ผู้รับเรื่อง วันส่งต่อ วันครบกำหนด และผลดำเนินการ |
| เรื่องอาจค้างนานหรือตกหล่น | ตรวจเรื่องใกล้ครบกำหนด เกิน SLA และเรื่องที่ไม่มีการอัปเดตโดยอัตโนมัติ |
| ประชาชนต้องโทรสอบถามความคืบหน้า | มีหน้า Public Tracking, Citizen Portal และการติดตามผ่าน LINE |
| การสรุปสถิติและจัดทำรายงานใช้เวลามาก | มี Dashboard รายงานแยกมิติ บทสรุปผู้บริหาร และ Export Excel |
| ตรวจสอบย้อนหลังได้ยากว่าใครทำอะไร | เก็บ Status Log, Timeline และ Audit Log ของ Action สำคัญ |
| ข้อมูลส่วนบุคคลอาจถูกเปิดเผยเกินความจำเป็น | จำกัดสิทธิ์ตามบทบาท ขอบเขตหน่วยงาน และปกปิดตัวตนตามกติกา |

## 3. วัตถุประสงค์

- ทำให้การรับและบันทึกเรื่องร้องเรียนมีรูปแบบเดียวกัน
- ลดระยะเวลาและขั้นตอนในการประสานงานระหว่างศูนย์ดำรงธรรมกับหน่วยงาน
- ทำให้สถานะ ผู้รับผิดชอบ และประวัติการดำเนินงานตรวจสอบย้อนหลังได้
- ให้ประชาชนติดตามเรื่องได้โดยไม่ต้องติดต่อเจ้าหน้าที่ทุกครั้ง
- ลดเรื่องตกหล่นด้วยระบบ SLA การเร่งรัด และการแจ้งเตือน
- สนับสนุนผู้บริหารด้วยข้อมูลสถิติและรายงานที่อัปเดตจากฐานข้อมูลเดียวกัน
- คุ้มครองข้อมูลส่วนบุคคลและจำกัดการเข้าถึงตามหน้าที่

## 4. กลุ่มผู้ใช้งาน

| กลุ่มผู้ใช้ | บทบาทในระบบ | การใช้งานหลัก |
|---|---|---|
| ประชาชนทั่วไป (Guest) | ไม่ต้อง Login | ยื่นเรื่องผ่านหน้าเว็บและติดตามด้วยเลขที่เรื่อง |
| สมาชิกประชาชน (Citizen) | บัญชีประชาชนแยกจาก Staff | สมัคร/Login, ยื่นเรื่อง, ดูเรื่องของตน, จัดการโปรไฟล์และการแจ้งเตือน |
| `officer`, `chief` | เจ้าหน้าที่และหัวหน้าศูนย์ดำรงธรรม | รับเรื่อง คัดกรอง ส่งต่อ ติดตาม ตรวจผล และปิดเรื่อง |
| `agency_officer`, `agency_head` | เจ้าหน้าที่และหัวหน้าหน่วยงานปลายทาง | รับหรือส่งคืนเรื่อง ดำเนินการ อัปเดตความคืบหน้า และส่งผลกลับ |
| `executive` | ผู้บริหาร | ดู Dashboard และรายงานแบบ Read-only |
| `admin` | ผู้ดูแลระบบ | จัดการเรื่อง ผู้ใช้ หน่วยงาน Master Data รายงาน และ Audit Log ตามสิทธิ์ |
| `super_admin` | ผู้ดูแลระบบสูงสุด | จัดการระบบทั้งหมด รวมถึง Action ที่จำกัดเฉพาะผู้ดูแลสูงสุด |

บัญชี Citizen ไม่ใช่ Role ในกลุ่มเจ้าหน้าที่ ระบบแยกข้อมูลบัญชี Token และเส้นทาง API ของ Citizen ออกจาก Staff เพื่อไม่ให้ใช้สิทธิ์ข้ามกัน

รายละเอียดสิทธิ์และบัญชีสำหรับทดสอบดูที่ [Roles, Permissions และบัญชีทดสอบ](./ROLES_AND_TEST_ACCOUNTS.md)

## 6. ฟีเจอร์ที่ระบบทำได้

### 6.1 รับเรื่องร้องเรียนจากหลายช่องทาง

ระบบรองรับการนำเรื่องเข้าสู่ระบบหลายรูปแบบ ได้แก่

- **หน้าเว็บสาธารณะ** — ประชาชนยื่นเรื่องได้โดยไม่ต้องสมัครสมาชิก
- **Citizen Portal** — สมาชิก Login แล้วยื่นเรื่องและดูรายการเรื่องของตนได้
- **เจ้าหน้าที่บันทึกแทนประชาชน** — ใช้สำหรับเรื่องจากจดหมาย ลงพื้นที่ ตู้ราชสีห์ สายด่วน 1567, Walk In, เว็บไซต์, แอป MOI1567, หน่วยงานอื่น และช่องทางอื่น ๆ
- **LINE Official Account** — รับเรื่องผ่านขั้นตอนสนทนา แจ้งเลขที่เรื่อง และเชื่อมเรื่องเข้ากับบัญชีประชาชน

ทุกช่องทางบันทึกเข้าสู่ฐานข้อมูลและใช้ Workflow เดียวกัน โดยเรื่องใหม่เริ่มที่สถานะ `NEW`

### 6.2 แบบฟอร์มร้องเรียนและหลักฐาน

ข้อมูลที่ระบบรองรับประกอบด้วย

- ข้อมูลผู้ร้องและเบอร์โทรศัพท์สำหรับติดต่อ
- การเลือกยื่นแบบเปิดเผยหรือปกปิดตัวตน
- หัวข้อ รายละเอียด ผู้เกี่ยวข้อง และสิ่งที่ต้องการให้ช่วยเหลือ
- ประเภทเรื่อง ประเภทงานบริการ ลักษณะเรื่อง และประเภทผู้ร้อง
- ระดับความสำคัญและช่องทางที่รับเรื่อง
- จุดเกิดเหตุแบบจังหวัด อำเภอ ตำบล รหัสไปรษณีย์ และรายละเอียดสถานที่
- การเลือกพิกัดบนแผนที่หรือใช้ตำแหน่งปัจจุบันจาก GPS
- ไฟล์หลักฐานประเภท JPG, JPEG, PNG, PDF, DOC และ DOCX ขนาดไม่เกิน 10 MB ต่อไฟล์

### 6.3 การปกปิดตัวตนและคุ้มครองข้อมูลผู้ร้อง

- ประชาชนเลือก `Anonymous` ได้ขณะยื่นเรื่อง
- เรื่อง Anonymous ใช้ Workflow เดียวกับเรื่องทั่วไป แต่ข้อมูลผู้ร้องถูก Mask จาก Staff
- เจ้าหน้าที่หน่วยงานปลายทางเห็นเฉพาะข้อมูลที่จำเป็นต่อการดำเนินงาน และไม่เห็นข้อมูลส่วนบุคคลของผู้ร้อง
- เฉพาะ `super_admin` ที่ขอเปิดเผยตัวตนของเรื่อง Anonymous ได้ โดยต้องระบุเหตุผล
- การเปิดเผยตัวตนและ Action สำคัญถูกบันทึกเพื่อให้ตรวจสอบย้อนหลังได้

### 6.4 Citizen Portal สำหรับประชาชนสมาชิก

สมาชิกประชาชนสามารถ

- สมัครสมาชิกและ Login ด้วยอีเมล/รหัสผ่าน หรือ LINE Login
- กรอกหรือแก้ไขโปรไฟล์ และเปลี่ยนหรือตั้งรหัสผ่าน
- ยื่นเรื่องโดยนำข้อมูลจากโปรไฟล์มาเติมในแบบฟอร์ม
- ดูรายการและรายละเอียดเรื่องของตนเอง
- ติดตามสถานะและความคืบหน้าที่เปิดเผยต่อประชาชน
- เชื่อม/ยกเลิกการเชื่อมบัญชี LINE
- ตั้งค่าประเภทการแจ้งเตือนที่ต้องการรับทาง LINE

ข้อมูลผู้ร้องในแต่ละเรื่องถูกเก็บเป็น Snapshot ณ เวลาที่ยื่น การแก้โปรไฟล์ภายหลังจึงไม่เปลี่ยนข้อมูลย้อนหลังของเรื่องเดิม

### 6.5 การรับเรื่องและติดตามผ่าน LINE Official Account

LINE รองรับภารกิจหลักดังนี้

- รับเรื่องร้องเรียนด้วย Wizard ในแชตและ Rich Menu
- แจ้งเลขที่รับเรื่องอัตโนมัติหลังบันทึกสำเร็จ
- แสดงสถานะของเรื่องที่ผูกกับบัญชี LINE ของผู้ใช้
- ให้เจ้าหน้าที่ขอข้อมูลหรือเอกสารเพิ่มเติม และให้ประชาชนตอบกลับในแชต
- แจ้งผลหรือสถานะสำคัญ และให้เจ้าหน้าที่ส่งสถานะปัจจุบันซ้ำได้
- ให้เจ้าหน้าที่ศูนย์หรือหน่วยงานที่ถือเรื่องพิมพ์ข้อความเพิ่มเติมถึงผู้ร้องได้ โดยตรวจทานก่อนเข้าคิวส่ง

ร่างการสนทนาที่ค้างอยู่มีอายุ 60 นาที ระบบรองรับการย้อนกลับ ยกเลิก หรือเริ่มใหม่ และดูแลล้างร่าง/ข้อมูลชั่วคราวตามระยะเวลาที่กำหนด

### 6.6 งานของเจ้าหน้าที่ศูนย์ดำรงธรรม

เจ้าหน้าที่ศูนย์สามารถ

- ค้นหา กรอง และดูรายละเอียดเรื่องร้องเรียน
- สร้างหรือแก้ไขข้อมูลเรื่องตามสิทธิ์
- เริ่มคัดกรอง จัดประเภท กำหนดความสำคัญ และตรวจข้อมูลพื้นที่
- ส่งต่อเรื่องไปยังหน่วยงานที่รับผิดชอบ หรือเลือกให้ศูนย์จัดการเอง
- ปฏิเสธเรื่องพร้อมเหตุผลตามเงื่อนไข
- ดู Timeline, Assignment, ความคืบหน้า และไฟล์แนบ
- ขอข้อมูลหรือเอกสารเพิ่มเติมจากผู้ร้องผ่าน LINE
- พิมพ์ข้อความเพิ่มเติมถึงผู้ร้องในแท็บ LINE และยืนยันก่อนส่งเข้าคิว
- ตรวจผลที่หน่วยงานส่งกลับ ส่งกลับไปแก้ไข หรือปิดเรื่องพร้อมสรุปผล
- ส่งแจ้งสถานะปัจจุบันให้ประชาชนทาง LINE ซ้ำโดยไม่เปลี่ยนสถานะเรื่อง

### 6.7 งานของหน่วยงานที่รับผิดชอบ

เจ้าหน้าที่หน่วยงานปลายทางสามารถ

- เห็นเฉพาะเรื่องที่ส่งให้หน่วยงานของตน
- รับเรื่องหรือส่งคืนเรื่องพร้อมเหตุผล
- เริ่มดำเนินการและบันทึกความคืบหน้า
- แนบเอกสารประกอบและขอข้อมูลเพิ่มเติมจากผู้ร้อง
- พิมพ์ข้อความเพิ่มเติมถึงผู้ร้องของเรื่องที่หน่วยงานรับผิดชอบผ่านแท็บ LINE
- ส่งผลดำเนินการกลับให้ศูนย์ตรวจสอบ
- ดู Dashboard ที่จำกัดข้อมูลตามหน่วยงาน

### 6.8 Workflow, Timeline และการตรวจสอบย้อนหลัง

- ควบคุมลำดับสถานะเพื่อป้องกันการข้ามขั้นตอนที่ไม่อนุญาต
- เก็บผู้ดำเนินการ เวลา สถานะเดิม สถานะใหม่ และหมายเหตุที่เกี่ยวข้อง
- แสดง Timeline รวมเหตุการณ์สำคัญของเรื่อง
- เก็บประวัติการมอบหมายและความคืบหน้า
- เก็บ Audit Log สำหรับ Action สำคัญของผู้ใช้งานและระบบ

### 6.9 SLA และการเร่งรัดเรื่องค้าง

ระบบมีกลไกติดตาม 2 แบบซึ่งทำงานแยกจากกัน

1. **SLA** — คำนวณวันครบกำหนดจากวันที่ส่งต่อหรือเริ่มให้ศูนย์จัดการเอง บวกจำนวนวัน SLA ของประเภทเรื่อง ระบบแจ้งเมื่อเหลือ 3 วันและทำเครื่องหมายเมื่อเกินกำหนด
2. **Escalation** — ตรวจเรื่องที่ไม่มีการอัปเดตความคืบหน้า และยกระดับการเร่งรัดเป็น L1, L2 และ L3

ผู้ดูแลระบบสามารถเปิด/ปิดการเร่งรัดและปรับจำนวนวันของแต่ละระดับผ่านหน้า Settings โดยค่าตั้งต้นคือ L1 ที่ 30 วัน, L2 เพิ่มอีก 15 วัน และ L3 เพิ่มอีก 7 วัน ระบบตรวจ SLA และ Escalation ทุกวันเวลา 08:00 น. ตามเขตเวลา Asia/Bangkok

รายละเอียดดูที่ [เรื่องที่ถูกเร่งรัดและเรื่องเกินกำหนด SLA](./SLA_AND_ESCALATION.md)

### 6.10 การแจ้งเตือน

ระบบรองรับ

- การแจ้งเตือนภายใน Web Application พร้อมสถานะอ่าน/ยังไม่อ่าน
- การตรวจจำนวนแจ้งเตือนใหม่เป็นระยะ
- LINE ส่วนบุคคลสำหรับประชาชนและเจ้าหน้าที่ที่เชื่อมบัญชีไว้
- LINE Group สำหรับศูนย์ดำรงธรรมและหน่วยงานตามสิทธิ์
- การตั้งค่าประเภทข้อความที่ผู้ใช้ต้องการรับ
- คิวส่งข้อความแบบ Outbox พร้อม Retry เมื่อส่งไม่สำเร็จชั่วคราว

ตัวอย่างเหตุการณ์ที่ทำให้เกิดการแจ้งเตือน ได้แก่ เรื่องใหม่ การส่งต่อ การรับหรือส่งคืนเรื่อง การอัปเดตความคืบหน้า การส่งผล การปิดเรื่อง การขอข้อมูลเพิ่มเติม เรื่องใกล้ครบกำหนด เรื่องเกิน SLA และการเร่งรัด

### 6.11 Dashboard

Dashboard แสดงข้อมูลตามสิทธิ์และขอบเขตหน่วยงานของผู้ใช้งาน ประกอบด้วย

- จำนวนเรื่องทั้งหมดและจำนวนตามสถานะ
- งานค้างของศูนย์ เช่น เรื่องใหม่ กำลังคัดกรอง และรอตรวจผล
- งานของหน่วยงาน เช่น รอรับเรื่อง กำลังดำเนินการ และส่งผลแล้ว
- เรื่องใกล้ครบกำหนด เกิน SLA และเรื่องที่ถูกเร่งรัด
- แนวโน้มรายเดือนและสัดส่วนตามสถานะ
- สถิติตามประเภทเรื่องและตามหน่วยงาน
- ตัวกรองช่วงวันที่และการกดจากการ์ดเพื่อไปยังรายการที่เกี่ยวข้อง

ผู้ใช้ระดับหน่วยงานเห็นข้อมูลเฉพาะหน่วยงานของตน ส่วนผู้บริหารดูข้อมูลภาพรวมแบบ Read-only

### 6.12 รายงานและบทสรุปผู้บริหาร

ระบบจัดทำรายงานได้หลายมิติ ได้แก่

- บทสรุปผู้บริหารที่สร้างข้อความจากตัวเลขในระบบ เลือกช่วงเวลา/หน่วยงานและคัดลอกข้อความไปใช้ต่อได้
- รายงานรายเดือน พร้อมจำนวนรับเรื่อง ปิดเรื่อง เกินกำหนด และอัตราปิด
- รายงานตามประเภทเรื่อง
- รายงานตามหน่วยงาน
- รายการเรื่องเกินกำหนด SLA
- การกรองตามช่วงวันที่และหน่วยงานในรายงานที่รองรับ
- Export รายงานเป็นไฟล์ Excel

บทสรุปที่ระบบสร้างเป็นข้อมูลช่วยร่าง ผู้ใช้งานควรตรวจสอบความครบถ้วนและปรับถ้อยคำก่อนนำไปใช้ในเอกสารราชการ

### 6.13 การจัดการข้อมูลระบบ

ผู้ดูแลระบบสามารถ

- จัดการผู้ใช้งาน เปิด/ปิดบัญชี และ Reset Password
- จัดการหน่วยงานและสถานะการใช้งาน
- จัดการ Master Data ได้แก่ ประเภทเรื่องและค่า SLA, ช่องทางรับเรื่อง, ประเภทงานบริการ, ลักษณะเรื่อง และประเภทผู้ร้อง
- เปิด/ปิดและกำหนดระดับวันของ Escalation
- จัดการกลุ่ม LINE ที่ใช้รับการแจ้งเตือนตามสิทธิ์
- ตรวจสอบ Audit Log และรายละเอียดเหตุการณ์ย้อนหลัง

ข้อมูลจังหวัด อำเภอ และตำบลใช้เป็นข้อมูลอ้างอิงสำหรับจุดเกิดเหตุ โดยจังหวัดศรีสะเกษเป็นค่าเริ่มต้นของระบบ

### 6.14 คู่มือการใช้งานตามบทบาท

ระบบมีหน้าคู่มือภายในแอปซึ่งแสดงเนื้อหาตามผู้ใช้งานแต่ละกลุ่ม

- Staff ทุก Role เปิดเมนู **คู่มือการใช้งาน** และเห็นคู่มือที่ตรงกับ Role ของตน
- `super_admin` และ `admin` เลือกแท็บเพื่อดูคู่มือ Staff ทุก Role รวมถึงคู่มือ Public และ Citizen ได้
- Citizen ที่ Login แล้วเปิดคู่มือจากแถบเมนูหรือเมนูบัญชี และเห็นเฉพาะคู่มือ Citizen
- ประชาชนทั่วไปเปิดคู่มือ Public ได้โดยไม่ต้อง Login
- เส้นทาง Staff, Citizen และ Public แยกกัน เพื่อไม่ใช้บัญชีหรือสิทธิ์ข้ามประเภทผู้ใช้

## 7. หลักการด้านสิทธิ์และความปลอดภัย

- Staff และ Citizen ใช้ JWT แยกประเภทกัน
- ควบคุมสิทธิ์แบบ Role-Based Access Control ทั้งหน้าเว็บและ Backend API
- จำกัดข้อมูลของผู้ใช้หน่วยงานให้เห็นเฉพาะเรื่องที่หน่วยงานรับผิดชอบ
- กรองและ Mask ข้อมูลส่วนบุคคลจาก Backend ไม่อาศัยเพียงการซ่อนบนหน้าจอ
- รหัสผ่านจัดเก็บด้วย bcrypt hash
- ตรวจสอบข้อมูลก่อนประมวลผลและใช้ Parameterized Query กับ MySQL
- จำกัดความถี่ของ Endpoint สำคัญ เช่น Login และการยื่นเรื่องสาธารณะ
- ตรวจชนิด MIME, นามสกุล และขนาดไฟล์ก่อนรับ Upload
- ตรวจลายเซ็น `X-Line-Signature` ของ LINE Webhook และป้องกันการประมวลผล Event ซ้ำ
- ใช้ Security Headers และ CORS ตามค่าที่กำหนด
- บันทึก Audit Log และประวัติการเปิดเผยตัวตนเพื่อรองรับการตรวจสอบย้อนหลัง

## 8. ขอบเขตของระบบปัจจุบัน

- ใช้ภาษาไทยเป็นหลักและออกแบบเพื่อการทำงานของจังหวัดศรีสะเกษ
- การแจ้งเตือนบนหน้าเว็บใช้การตรวจสอบเป็นระยะ ไม่ได้ใช้ WebSocket
- ไฟล์แนบเก็บใน Local Disk หรือ Persistent Volume ตามสภาพแวดล้อมที่ติดตั้ง
- SLA นับเป็นวันตามปฏิทิน รวมวันเสาร์ อาทิตย์ และวันหยุด
- ระบบไม่รองรับการเปิดเรื่อง `CLOSED` หรือ `REJECTED` กลับมาดำเนินการใหม่
- Citizen ยังไม่มี Email Verification/OTP, Social Login หรือการลบบัญชีแบบถาวร
- ช่องทางแจ้งเตือนหลักในระบบปัจจุบันคือ In-app และ LINE ยังไม่มี Email หรือ SMS
- LINE Intake ยังไม่รองรับ LIFF Form, ข้อความเสียง หรือวิดีโอ
- ระบบออกแบบสำหรับ Desktop และ Tablet เป็นหลัก แม้หน้าสาธารณะและ Citizen Portal จะใช้งานบนโทรศัพท์ได้

## 9. ภาพรวมเทคโนโลยี

| ส่วน | เทคโนโลยีหลัก |
|---|---|
| Frontend | React 18, Vite 5, Material UI, React Router, Axios, Recharts, Leaflet |
| Backend | Node.js 20, Express 4, JWT, bcrypt, Multer, node-cron |
| Database | MySQL 8, Raw SQL ผ่าน `mysql2`, ชุดอักขระ `utf8mb4` |
| รายงาน | ExcelJS สำหรับสร้างไฟล์ Excel |
| Development | Docker Compose พร้อม Frontend, Backend, MySQL และ phpMyAdmin |
| Production | รองรับการ Build แบบรวม Frontend/Backend และติดตั้งผ่าน Docker หรือ Shared Server ตามคู่มือ Deployment |

Backend แยกความรับผิดชอบเป็น Route → Controller → Service → Model → Database ส่วนงานตรวจ SLA, Escalation, คิวแจ้งเตือน และการดูแลข้อมูล LINE ทำงานผ่าน Scheduled Jobs
