# Complaint Workflow — Damrongdham SSK

## สถานะทั้งหมด (Status)

| สถานะ | สี | ผู้รับผิดชอบ | ความหมาย |
|---|---|---|---|
| `NEW` | 🔵 น้ำเงิน | ศูนย์ดำรงธรรม | รับเรื่องใหม่เข้าระบบ ยังไม่ได้คัดกรอง |
| `SCREENING` | 🔵 น้ำเงิน | ศูนย์ดำรงธรรม | อยู่ระหว่างคัดกรองว่ารับหรือปฏิเสธ |
| `ASSIGNED` | 🔵 น้ำเงิน | ศูนย์ดำรงธรรม | ส่งต่อหน่วยงานแล้ว รอหน่วยงานรับเรื่อง |
| `ACCEPTED` | 🟢 เขียว | หน่วยงาน | หน่วยงานรับเรื่องแล้ว รอเริ่มดำเนินการ |
| `IN_PROGRESS` | 🟢 เขียว / 🔵 น้ำเงิน | หน่วยงาน / ศูนย์ | กำลังดำเนินการ (หน่วยงาน หรือศูนย์จัดการเอง) |
| `RESOLVED` | 🟢 เขียว | หน่วยงาน | หน่วยงานส่งผลการดำเนินการแล้ว รอศูนย์ตรวจ |
| `REVIEWING` | 🔵 น้ำเงิน | ศูนย์ดำรงธรรม | ศูนย์กำลังตรวจสอบผลที่หน่วยงานส่งมา |
| `RETURNED` | 🟠 ส้ม | — | หน่วยงานส่งคืนเรื่อง รอศูนย์คัดกรองใหม่ |
| `CLOSED` | 🔴 แดง | — | ปิดเรื่องสำเร็จ (จุดสิ้นสุด) |
| `REJECTED` | 🔴 แดง | — | ปฏิเสธเรื่อง (จุดสิ้นสุด) |

---

## Transitions (การเปลี่ยนสถานะ)

### ศูนย์ดำรงธรรม

| รหัส | จาก → ไป | Action | เงื่อนไข |
|---|---|---|---|
| T-01 | `NEW → SCREENING` | เริ่มคัดกรอง | — |
| T-03 | `SCREENING → REJECTED` | ปฏิเสธเรื่อง | ต้องระบุเหตุผล |
| T-02 | `SCREENING → ASSIGNED` | ส่งต่อหน่วยงาน | ต้องเลือกหน่วยงาน ระบบจะคำนวณ SLA due date |
| Self | `SCREENING → IN_PROGRESS` | ศูนย์จัดการเอง | ศูนย์รับดำเนินการแทนหน่วยงาน |
| T-09 | `RESOLVED → REVIEWING` | เริ่มตรวจผล | — |
| T-10 | `REVIEWING → CLOSED` | ปิดเรื่อง | ต้องระบุสรุปผลการดำเนินการ |
| T-11 | `REVIEWING → IN_PROGRESS` | ส่งกลับให้แก้ไข | ผลไม่ผ่าน ส่งกลับหน่วยงาน |
| T-12 | `RETURNED → SCREENING` | เริ่มคัดกรองใหม่ | หน่วยงานส่งคืนเรื่องมาแล้ว |

### หน่วยงาน

| รหัส | จาก → ไป | Action | เงื่อนไข |
|---|---|---|---|
| T-04 | `ASSIGNED → ACCEPTED` | รับเรื่อง | — |
| T-05 | `ASSIGNED → RETURNED` | ส่งคืน (ก่อนรับ) | ต้องระบุเหตุผล |
| T-06 | `ACCEPTED → IN_PROGRESS` | เริ่มดำเนินการ | — |
| T-07 | `ACCEPTED → RETURNED` | ส่งคืน (หลังรับ) | ต้องระบุเหตุผล |
| T-08 | `IN_PROGRESS → RESOLVED` | ส่งผลการดำเนินการ | ต้องระบุผลการดำเนินการ |

## หมายเหตุสำคัญ

- **SLA**: เมื่อส่งต่อหน่วยงาน (T-02) ระบบจะคำนวณ `due_date` อัตโนมัติตาม `sla_days` ของประเภทเรื่อง
- **Escalation**: เรื่องที่ไม่มีความเคลื่อนไหวเกิน 30/60/90 วัน จะถูกยกระดับเป็น L1/L2/L3
- **is_overdue**: เมื่อเลย `due_date` แล้ว ระบบ cron job จะ set `is_overdue = 1` ทุกวัน 08:00
- **Anonymous**: เรื่องที่ปกปิดตัวตน PII จะถูก mask อัตโนมัติ เปิดเผยได้เฉพาะ `super_admin` เท่านั้น
- **Delete**: ลบเรื่องถาวรได้เฉพาะ `super_admin` เท่านั้น (hard delete พร้อม audit log)

## สิทธิ์การเข้าถึง

| Role | สิ่งที่ทำได้ |
|---|---|
| `super_admin` | ทุกอย่าง รวมถึง delete และ reveal identity |
| `admin`, `officer`, `chief` | ทุก transition ของศูนย์ดำรงธรรม |
| `agency_head`, `agency_officer` | T-04, T-05, T-06, T-07, T-08 (เฉพาะหน่วยงานตัวเอง) |
| `executive` | ดูข้อมูลได้อย่างเดียว |
