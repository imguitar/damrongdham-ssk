## Workflow ที่ต้องใช้ในการทดสอบ

Workflow ปัจจุบันอ้างอิง `docs/planning/04-complaint-workflow.md`:

```text
NEW -> SCREENING -> ASSIGNED -> ACCEPTED -> IN_PROGRESS -> RESOLVED -> REVIEWING -> CLOSED
```

กรณีพิเศษ:

- `SCREENING -> REJECTED` เมื่อปฏิเสธเรื่อง
- `ASSIGNED/ACCEPTED -> RETURNED -> SCREENING` เมื่อหน่วยงานส่งคืน
- `SCREENING -> IN_PROGRESS -> CLOSED` เมื่อศูนย์ดำรงธรรมจัดการเองโดยไม่ส่งต่อหน่วยงาน
- `OVERDUE` ไม่ใช่สถานะ แต่เป็น flag `is_overdue`
- เลขที่เรื่องต้องอยู่ในรูปแบบ `DC-YYYYMM-XXXX`

## หมวด A — รับเรื่องร้องเรียน

### A-01: เจ้าหน้าที่สร้างเรื่องร้องเรียนใหม่

**ผู้ทดสอบ**: officer / chief / admin

**ขั้นตอน**:
1. Login ด้วยบัญชี officer
2. ไปที่เมนู "รายการเรื่องร้องเรียน"
3. คลิก "รับเรื่องใหม่"
4. กรอกข้อมูลจำเป็นให้ครบ รวมถึงเบอร์โทรศัพท์, ประเภทงานบริการ, ลักษณะเรื่อง, ประเภทผู้ร้องเรียน, จังหวัด/อำเภอ/ตำบล, สถานที่เกิดเหตุ และประเภทเรื่อง
5. กด "บันทึก"

**ผลลัพธ์ที่คาดหวัง**:
- [ ] สร้างเรื่องร้องเรียนสำเร็จ
- [ ] เลขที่เรื่องถูกสร้างอัตโนมัติในรูปแบบ `DC-YYYYMM-XXXX`
- [ ] สถานะเริ่มต้นเป็น `NEW`
- [ ] `source` เป็น staff หรือค่าที่ระบบกำหนดสำหรับเจ้าหน้าที่
- [ ] รายการใหม่ปรากฏในหน้ารายการเรื่องร้องเรียน
- [ ] Timeline แสดงเหตุการณ์สร้างเรื่อง

### A-02: ประชาชนยื่นเรื่องแบบ Guest

**ผู้ทดสอบ**: ประชาชน ไม่ต้อง login

**ขั้นตอน**:
1. เปิด URL `/public/complaints/new`
2. กรอกข้อมูลจำเป็นให้ครบ
3. แนบไฟล์หลักฐานที่รองรับ เช่น jpg, png, pdf, doc, docx
4. กดส่งเรื่อง

**ผลลัพธ์ที่คาดหวัง**:
- [ ] ยื่นเรื่องสำเร็จ
- [ ] ได้เลขที่เรื่องรูปแบบ `DC-YYYYMM-XXXX`
- [ ] สถานะเริ่มต้นเป็น `NEW`
- [ ] ไฟล์แนบถูกบันทึกและเปิดดูได้โดยผู้มีสิทธิ์
- [ ] ไม่ต้องมี `citizen_id`

### A-03: สร้างเรื่องแบบไม่เปิดเผยตัวตน

**ผู้ทดสอบ**: officer / citizen / guest

**ขั้นตอน**:
1. สร้างเรื่องร้องเรียนใหม่
2. เลือกตัวเลือก "ไม่เปิดเผยตัวตน"
3. บันทึกเรื่อง
4. Login ด้วย role ต่างๆ ที่ไม่ใช่ super_admin แล้วเปิดหน้ารายละเอียด

**ผลลัพธ์ที่คาดหวัง**:
- [ ] บันทึกเรื่องสำเร็จ
- [ ] `is_anonymous` ถูกบันทึกถูกต้อง
- [ ] ข้อมูลส่วนบุคคลผู้ร้องถูกซ่อนสำหรับ role ทั่วไป
- [ ] staff role ไม่เห็น `citizen_id` หรือข้อมูลที่ระบุตัวตนได้
- [ ] เฉพาะ super_admin เปิดเผยตัวตนได้พร้อมระบุเหตุผลและมี audit log

## หมวด B — Workflow หลักแบบส่งต่อหน่วยงาน

### B-01: เริ่มคัดกรองเรื่อง

**ผู้ทดสอบ**: officer / chief

**ขั้นตอน**:
1. เลือกเรื่องที่สถานะ `NEW`
2. คลิกเริ่มคัดกรองหรือรับเรื่องเข้าสู่การคัดกรอง

**ผลลัพธ์ที่คาดหวัง**:
- [ ] สถานะเปลี่ยนจาก `NEW` เป็น `SCREENING` (T-01)
- [ ] Timeline แสดงการเปลี่ยนสถานะ
- [ ] เรื่องพร้อมสำหรับการส่งต่อ, ปฏิเสธ หรือศูนย์จัดการเอง

### B-02: ส่งต่อเรื่องให้หน่วยงาน

**ผู้ทดสอบ**: officer / chief

**ขั้นตอน**:
1. เลือกเรื่องที่สถานะ `SCREENING`
2. เลือกหน่วยงานรับผิดชอบ
3. ระบุหมายเหตุถ้ามี
4. กดส่งต่อ

**ผลลัพธ์ที่คาดหวัง**:
- [ ] สถานะเปลี่ยนจาก `SCREENING` เป็น `ASSIGNED` (T-02)
- [ ] มี active assignment ของหน่วยงานที่เลือก
- [ ] `assigned_at` และ `due_date` ถูกคำนวณจาก SLA ของประเภทเรื่อง
- [ ] แจ้งเตือนหน่วยงานที่เกี่ยวข้อง
- [ ] Timeline แสดงการส่งต่อ

### B-03: หน่วยงานรับเรื่อง

**ผู้ทดสอบ**: agency_officer / agency_head

**ขั้นตอน**:
1. Login ด้วยบัญชีหน่วยงานที่ได้รับมอบหมาย
2. เปิดเรื่องที่สถานะ `ASSIGNED`
3. กดรับเรื่อง

**ผลลัพธ์ที่คาดหวัง**:
- [ ] สถานะเปลี่ยนจาก `ASSIGNED` เป็น `ACCEPTED` (T-04)
- [ ] assignment status เปลี่ยนเป็นรับเรื่องแล้ว
- [ ] Timeline แสดงว่าหน่วยงานรับเรื่อง

### B-04: หน่วยงานเริ่มดำเนินการ

**ผู้ทดสอบ**: agency_officer / agency_head

**ขั้นตอน**:
1. เปิดเรื่องที่สถานะ `ACCEPTED`
2. กดเริ่มดำเนินการ

**ผลลัพธ์ที่คาดหวัง**:
- [ ] สถานะเปลี่ยนจาก `ACCEPTED` เป็น `IN_PROGRESS` (T-06)
- [ ] Timeline แสดงการเริ่มดำเนินการ
- [ ] ยังไม่สามารถปิดเรื่องโดยศูนย์ได้โดยตรงถ้ามี active assignment

### B-05: หน่วยงานอัปเดตความคืบหน้า

**ผู้ทดสอบ**: agency_officer / agency_head

**ขั้นตอน**:
1. เปิดเรื่องที่สถานะ `IN_PROGRESS`
2. เพิ่มข้อความความคืบหน้า
3. แนบไฟล์ถ้ามี
4. บันทึก

**ผลลัพธ์ที่คาดหวัง**:
- [ ] Update ถูกบันทึกใน Timeline
- [ ] `last_progress_at` ถูกอัปเดต
- [ ] วงรอบ escalation ถูก reset ตามเงื่อนไขระบบ
- [ ] ประชาชนเห็นเฉพาะข้อมูลที่เปิดเผยได้

### B-06: หน่วยงานส่งผลดำเนินการ

**ผู้ทดสอบ**: agency_officer / agency_head

**ขั้นตอน**:
1. เปิดเรื่องที่สถานะ `IN_PROGRESS`
2. กดส่งผลดำเนินการ
3. กรอกรายละเอียดผลดำเนินการ
4. แนบหลักฐานถ้ามี

**ผลลัพธ์ที่คาดหวัง**:
- [ ] สถานะเปลี่ยนจาก `IN_PROGRESS` เป็น `RESOLVED` (T-08)
- [ ] ผลดำเนินการแสดงใน Timeline
- [ ] เจ้าหน้าที่ศูนย์ได้รับแจ้งเตือนให้ตรวจผล

### B-07: ศูนย์เริ่มตรวจสอบผล

**ผู้ทดสอบ**: officer / chief

**ขั้นตอน**:
1. เปิดเรื่องที่สถานะ `RESOLVED`
2. กดเริ่มตรวจสอบผล

**ผลลัพธ์ที่คาดหวัง**:
- [ ] สถานะเปลี่ยนจาก `RESOLVED` เป็น `REVIEWING` (T-09)
- [ ] Timeline แสดงการเริ่มตรวจสอบผล

### B-08: ศูนย์ปิดเรื่อง

**ผู้ทดสอบ**: officer / chief

**ขั้นตอน**:
1. เปิดเรื่องที่สถานะ `REVIEWING`
2. กดปิดเรื่อง
3. กรอก `closed_summary`

**ผลลัพธ์ที่คาดหวัง**:
- [ ] สถานะเปลี่ยนจาก `REVIEWING` เป็น `CLOSED` (T-10)
- [ ] `closed_at`, `closed_by`, `closed_summary` ถูกบันทึก
- [ ] เรื่องที่ `CLOSED` ไม่สามารถแก้ไขหรือเปลี่ยนสถานะต่อได้
- [ ] ประชาชนเห็นสถานะแบบย่อว่า "ดำเนินการเสร็จสิ้น"

**ผู้ทดสอบ**: officer / chief

**ขั้นตอน**:
1. เปิดเรื่องที่สถานะ `SCREENING`
2. กดปฏิเสธเรื่อง
3. ระบุ `rejection_reason`

**ผลลัพธ์ที่คาดหวัง**:
- [ ] สถานะเปลี่ยนจาก `SCREENING` เป็น `REJECTED` (T-03)
- [ ] เหตุผลปฏิเสธถูกบันทึก
- [ ] เรื่องที่ `REJECTED` ไม่สามารถแก้ไขหรือเปลี่ยนสถานะต่อได้
- [ ] ประชาชนเห็นสถานะแบบย่อว่าไม่สามารถดำเนินการได้ พร้อมเหตุผลที่เปิดเผยได้

### D-02: ตรวจสอบ transition ที่ต้องถูกปฏิเสธ

**ผู้ทดสอบ**: officer / chief / agency_officer

3. พยายามเปลี่ยนเรื่อง `REJECTED` ไปสถานะอื่น
4. พยายามเปลี่ยน `IN_PROGRESS` กลับเป็น `ASSIGNED`

**ผลลัพธ์ที่คาดหวัง**:
- [ ] ระบบปฏิเสธทุก transition ที่ไม่อนุญาต
- [ ] API คืน error ที่เหมาะสม
- [ ] ไม่มีข้อมูลสถานะผิดปกติใน Timeline

## หมวด H — Security & Permission

### H-01: ไม่สามารถเข้าถึง API โดยไม่มี Token

```bash
curl https://<domain>/api/complaints
# Expected: 401 Unauthorized
```

**ผลลัพธ์ที่คาดหวัง**:
- [ ] API คืน 401
- [ ] Response อยู่ในรูปแบบ `{ success: false, error: { code, message } }`

### H-02: Role ที่ไม่มีสิทธิ์เข้าถึง endpoint ไม่ได้

**ขั้นตอน**:
1. Login ด้วย agency_officer
2. พยายามเรียก admin-only endpoint เช่น `/api/users`
3. พยายามดู complaint ของหน่วยงานอื่น
4. Login ด้วย executive แล้วลองแก้ไขหรือเปลี่ยนสถานะเรื่อง

**ผลลัพธ์ที่คาดหวัง**:
- [ ] endpoint admin-only คืน 403
- [ ] agency user เห็นเฉพาะเรื่องของหน่วยงานตน
- [ ] executive อ่านได้ตามสิทธิ์ แต่แก้ไขไม่ได้
- [ ] Backend บังคับสิทธิ์จริง ไม่ใช่แค่ซ่อนปุ่มใน UI

### H-03: File Upload Security

**ขั้นตอน**:
1. แนบไฟล์ชนิดที่อนุญาต เช่น jpg, png, pdf, doc, docx
2. แนบไฟล์ชนิดที่ไม่อนุญาต เช่น exe, js, html
3. แนบไฟล์ใหญ่เกิน limit

**ผลลัพธ์ที่คาดหวัง**:
- [ ] ไฟล์ชนิดที่อนุญาต upload ได้
- [ ] ไฟล์ชนิดที่ไม่อนุญาตถูกปฏิเสธ
- [ ] ไฟล์ใหญ่เกิน limit ถูกปฏิเสธ
- [ ] download attachment ต้องผ่านสิทธิ์ที่ถูกต้อง
